Refactor proposal

Make one small canonical commit core.

Replace the 4,284-line sink with explicit ownership boundaries. The generic core commits provider-neutral facts. Turn policy, recovery policy, reads, publication, and Codex child coordination move out.

1durable, provider-neutral event contract
5focused services with named responsibilities
0unproven claims about the reported UI failure

Proposed decision: AgentTurn.status, reduced from committed canonical envelopes, is the durable terminal-state authority. The legacy event path remains a required compatibility projection until every implementation has migrated. A checkpoint is an execution-recovery journal, not a second state machine. Keep the one SQLite transaction, then publish matching canonical and legacy outputs from one explicit decision.

What we know

The current class has five incompatible jobs.

This is not a request to divide 4,284 lines by five. The split must replace hidden coupling with contracts that can be tested independently.

Durable commit

Validate drafts, reduce canonical state, persist state and envelopes, update the checkpoint, then publish committed events.

Parent turn policy

Start a turn, finalize it, project compatibility records, recover after restart, and decide terminal outcomes.

Reads and reconnect

Load conversation projections, query checkpoints, choose replay or snapshot, and resolve stop targets.

Provider ingress

Receive provider drafts through the host port and forward committed batches to the legacy bridge.

Codex collaboration

Delegate to children, bind native identities, record delivery uncertainty, retry, and resume parents.

SQL mapping

Perform database queries and map raw rows into domain records beside application policy.

Proven contract mismatch: the existing overflow fixture expects the durable checkpoint to say errored while the canonical reducer sets the turn status to Interrupted. That is two outputs for one terminal fact. It does not prove the reported normal-turn failure, but it proves that the terminal contract is not yet singular.

State contract

Providers supply evidence. The lifecycle decides state.

A provider does not set UI status directly. Each provider translator turns native signals into the same canonical drafts. A pure lifecycle decision validates the transition for one executionId.

One named result for every batch

type CanonicalAppendCommand = {
  stream: { threadId: string; turnId: string; executionId: string };
  events: readonly CanonicalAgentEventDraft[];
  nativeCursor?: ProviderIdentity;
};

type CanonicalCommitReceipt = {
  durability: "committed" | "duplicate" | "conflict";
  revision: CanonicalAgentRevision;
  acceptedThrough: number;
  events: readonly CanonicalAgentEventEnvelope[];
  checkpoint: CanonicalCheckpoint;
};

type CanonicalDeliveryReceipt = {
  commit: CanonicalCommitReceipt;
  publication: "published" | "deferred";
};

The input does not independently claim phase, terminal outcome, and event payload. The validated events derive checkpoint phase and terminal outcome. Publication failure cannot pretend a durable commit failed.

Required normalizer: LifecycleDecision returns continue, ignore, or an evidence-backed terminal outcome. Transport closure is evidence, not an automatic Interrupted result. The decision owns the mapping. Provider code only supplies the source signal and native identity.

Checkpoint

A checkpoint is a recovery journal, not turn state.

It is written atomically with canonical envelopes so reconnect and restart can answer: which execution was accepted, how far did it persist, and is the terminal event materialized?

What it records

IdentityThread, turn, and execution that own this journal.
ProgressLast accepted provider sequence and durable canonical revision.
Resume pointOptional native cursor for safe provider continuation.
Recovery factDerived phase, terminal outcome, error detail, and update time.

What it must not do

Not UI statusThe renderer reads canonical turn state from committed events and snapshots.
Not provider policyIt cannot infer a terminal outcome from a provider transport event.
Not a second reducerIt cannot disagree with the canonical lifecycle about whether a turn ended or why.
Not a callback hostCompatibility projection needs explicit transactional data, not arbitrary functions inside the commit.

Target shape

A facade is a small door, not another god service.

The temporary facade preserves composition while callers migrate. The permanent design gives each caller a narrow port with a named outcome.

Safe migration

Extract by contract, with a proof at every boundary.

Each stage can ship without changing provider behavior. A stage moves ownership only after its old and new paths agree on persisted events, checkpoint, and rendered terminal state.

Proof of safety

The refactor is done only when these stay true.

Tests need to exercise the actual seam: provider evidence, lifecycle decision, durable transaction, recovery, and the renderer replica.

Contract and persistence checks

✓

One terminal fact: event payload, AgentTurn.status, checkpoint terminal outcome, compatibility outcome, and rendered status agree.

✓

Every transition: cover allowed transitions, duplicate terminal events, and every conflicting terminal pair.

✓

Atomicity: a failed participant rolls back state, envelopes, checkpoint, and publication.

✓

Publication: a post-commit publish failure produces deferred while durable replay repairs the client.

✓

Complexity: every new, extracted, or materially changed production function measures cyclomatic complexity of 10 or less.

Provider, recovery, and UI checks

✓

Provider conformance: the same canonical lifecycle sequence has the same terminal result for Claude, Codex, Copilot, and Cursor fixtures.

✓

Restart matrix: restart after start, progress, terminal persistence, and projection. Preserve a known terminal result.

✓

Codex graph: exercise single, sequential, parallel, and nested child agents, including uncertain delivery and retry.

✓

Active delivery paths: test live canonical push, reconnect delta, snapshot recovery, and matching legacy terminal events for every current implementation.

Release gate: run focused server and browser tests for each stage, then bun run verify:changed. For the final stage, run the narrative guide's single, sequential, parallel, and nested scenarios and verify both live and reload state.

Open risks

These need a deliberate answer during implementation.

They are not reasons to retain the current class. They are the contracts that a safe refactor must preserve or clarify.

Which channel currently owns the displayed terminal status?

The browser receives both agent.canonical and legacy agent.event. Both remain active until provider migration finishes. The stage-zero fixture must prove that they produce equivalent terminal results for their current consumers.

How does bounded terminal finalization publish partial progress?

Batched finalization can publish earlier batches before the terminal batch. Preserve that recovery contract, document it in the receipt, and test a restart at each boundary.

How do Codex parent and child writes remain atomic?

Do not split Codex methods one at a time. The collaboration coordinator must build an ordered, generic multi-stream mutation plan for the atomic store, with grouped publication after commit.

What closes a turn after a provider transport ends?

The lifecycle normalizer needs a typed evidence rule. A provider transport closure is not enough by itself to rewrite a completed or cancelled turn as interrupted.
