Protocol ledger / implementation plan
Codex provider completeness

Typed ingress. Clear ownership. Small slices.

A plan for Codex protocol coverage that keeps provider data bounded, keeps Mcode state authoritative, and adds only the capabilities that Mcode can own.

Decision

Provider input ends at typed ingress. The UI receives canonical Mcode data only. Provider-native turn diffs improve Last turn attribution, while Git snapshots remain the final filesystem record.

Boundary rules

Decisions that limit the surface area

Decision

Allow schema-valid notifications by default at typed provider ingress. Classify each notification exhaustively as map, state-only, diagnostic, or ignored-with-reason. An unknown event becomes a bounded diagnostic. It never reaches the UI as a raw provider payload.

Decision

Mcode owns local file watching and local reads. Direct local readFile, readDirectory, and getMetadata stay simple. Mcode does not expose provider fs/writeFile, remove, or copy, because those calls split permission and audit ownership.

Decision

A valid provider-native turn diff is preferred for the agent-attributed Last turn view. Git snapshots remain the safety and fallback source, the cumulative and worktree source, and the final filesystem-state record. Current snapshot RPCs filter to agent-attributed paths, but compare the full ref_before/ref_after tree for those paths. An unrelated edit to the same file during the turn can enter that displayed diff.

Decision

Auto-review is a separate policy from full access. It uses capability detection and visible lifecycle events. It falls back to the existing manual approval route when strict review is required.

Architecture decision packets

Decide the seams before expanding a provider.

Decision

Static capability, live support

Keep IAgentProvider small. Put finite static names such as approval-review and turn-diff on the provider descriptor. Static support means the adapter implements a feature. It does not mean that feature is usable for a specific turn. Add optional IApprovalReviewCapable for side-effect-free inspection that returns available, required, or unavailable, allowed modes, stable reason codes, and exact live-change scope. Do not add supportsAutoReview.

Decision

Resolve one request

Put resolved approvalReviewMode: "manual" | "automatic" and the resolved permission mode at the top level of TurnRequest. Do not put either in Codex-only providerOptions or send unresolved "default". Admission computes the effective permission mode near turn-admission-dispatch-coordinator.ts:689, but the current request uses the command or default near :898.

Decision

Policy routes. Adapter maps.

A server-owned ApprovalReviewPolicy combines user intent, Mcode permission rules, and provider support. It does not parse provider config such as requirements.toml. The adapter maps the generic mode to native turn config and native lifecycle to bounded canonical events. The policy never resolves permissions. strictReviewRequired only routes to manual review. A real provider-initiated request still uses the existing PermissionRequest flow.

Decision

Freeze at dispatch

Initial selection travels atomically with sendTurn. Do not add a pre-send configure method. A future live reviewer update is a separate command and stays out of the first slice. Codex live changes affect future captures only, not pending approvals or child sessions. Automatic review and Full Access are separate axes. Full Access skips Guardian and is never reviewed. Incompatible automatic review uses visible manual fallback. Managed automatic review that cannot run blocks the turn.

Recommended

Extend providers at the boundary

A future provider advertises a capability, implements support inspection, maps generic mode to native turn config, maps native lifecycle to canonical events, routes real manual requests through PermissionRequest, and passes shared conformance tests. Core and UI do not change. Inspection stays side-effect-free. One decision freezes per dispatch attempt. Persistence, request, sandbox, and UI use the same effective permission mode. A provider-native reviewer or validated user response alone resolves review. Review identity stays stable, only one terminal outcome exists, and manual-required is inactive until a real permission request arrives. Do not persist unstable raw provider risk payloads.

Decision

Turn diff evidence boundary

Keep optional push ITurnDiffSource, keyed by Mcode turnId, turnExecutionId, deliveryAttempt, and monotonic revision. The provider supplies only native evidence and native fidelity. Its states are snapshot, explicit invalidated, and indeterminate-empty for providers such as Codex that cannot distinguish valid empty aggregate from tracker invalidation. TurnDiffService owns reconciliation, fallback choice, final persistence, and stale retry rejection.

Decision

Persist settled evidence

Use a separate provider-neutral settled record keyed one-to-one by assistant message, independent of Git TurnSnapshot. Keep live revisions in memory. Store source, fidelity, and validated unified diff. Reject an oversized or malformed native patch as evidence and choose fallback. Do not truncate a patch. Set the exact byte threshold during implementation unless repository evidence defines it. Last turn shows Live evidence, then the settled record after completion or reconnect. Cumulative, branch, staged, unstaged, and commit views stay Git-backed.

Decision

Delay watchers and raw ingress

Use a server-owned local WorkspaceInvalidationSource only after at least two named consumers need it. Add remote IWorkspaceChangeSource only when a real remote workspace adapter exists. Validate canonical root containment, debounce and bound paths, and invalidate the whole workspace on overflow. Do not add local watch or mutation methods to IAgentProvider. Raw protocol notifications stay in each adapter. Typed mappers classify them before generic ingress accepts only canonical ProviderRuntimeEvent. Do not create a raw event bridge. The generic-shaped post-ingress ProviderEventAdapter currently receives a Codex-specific token. Generalize that registry only when a second post-ingress adapter exists.

Typed ingress workbench

One ledger for every accepted notification

The registry is the review point for new Codex notifications. It checks the schema, selects one disposition, bounds diagnostic data, and only then emits a canonical event or state change.

Disposition Use Boundary rule
Map Emit a typed, canonical Mcode contract event. Map named fields only. Redact and bound content before it crosses the provider layer.
State-only Update provider session state with no user-facing event. Keep the state local to the adapter or server session unless another layer needs a contract.
Diagnostic Record a bounded, typed diagnostic for an unsupported or operational event. Keep an event name, category, and redacted summary. Do not retain raw payloads.
Ignored with reason Do not emit or persist an event that Mcode cannot use. Name the reason in the registry so a future change has an audit trail.
Unknown Accept only after the schema validates, then write a bounded diagnostic. Unknown does not mean unsafe. It must not create UI data or bypass typed handling.

Registry output

Use a finite classification map next to the Codex event mapper. The map documents every accepted notification type and makes the default path visible in review.

Decision

No raw payload bridge

Do not store or render raw Codex notification objects. The provider adapter owns validation, field selection, redaction, and size limits.

Filesystem ownership

Watch locally first. Use provider watch only for a remote host.

Decision

Provider contract

fs/watch uses an absolute path and is scoped to one connection. It emits fs/changed with watchId and changedPaths. The provider debounces changes and cleans watches on disconnect. Mcode does not call it today.

Proposed

Shared Mcode watcher

Use one server-owned local watcher for the file tree, autocomplete, preview, and Review invalidation. Add this only when named consumers need the same invalidation stream.

Decision

Remote fallback

Use provider fs/watch only when a remote workspace makes the Mcode server watcher impossible. Keep direct local reads for normal local workspaces.

Decision

Mutation stays out

Do not expose fs/writeFile, remove, or copy through the Mcode provider surface. A second mutation route would divide permission and audit ownership.

Volatile diff channel

Use the latest full turn aggregate for live and settled Last turn evidence.

Decision

turn/diff/updated has the shape {threadId, turnId, diff}. It is the latest full aggregate for a turn, not an incremental patch stream. It can emit after tool results and at completion. It tracks exact patch changes and can invalidate to an empty diff.

Decision

A non-empty Codex update has stronger agent attribution than an attributed Git snapshot because it represents Codex-tracked patch changes. It is the preferred source for Last turn when it is valid and available.

Decision

Clear the Live preview on interrupt, rollback, replacement, and reconnect. An empty update can mean a net-zero edit or tracker invalidation. Reconcile it with Mcode file effects before final persistence, then use fallback evidence when effects remain.

Provider-neutral turn diff layer

Push evidence into one server-owned comparison record.

Decision

Do not add a provider pull method.

Do not add getTurnDiff() to IAgentProvider. Review can open after the provider session is gone, so a provider pull method has the wrong lifecycle.

Decision

Keep the seam small.

Add an optional ITurnDiffSource capability with a push subscription. Codex and Cursor supply real adapters. Claude uses the server fallback until it has native evidence.

Approval and review

Keep supervision, full access, and auto-review distinct.

Decision

Supervised

approvalPolicy: on-request, approvalsReviewer: user, and manual Mcode approval. The user remains the reviewer.

Decision

Full access

approvalPolicy: never with bypass. This is not review. It does not imply that any reviewer checked an action.

Decision

Auto-review

approvalsReviewer: auto_review or guardian_subagent, after capability detection. Its lifecycle remains visible and strict-review rules can divert it to manual approval.

Visible auto-review lifecycle

UnavailableCapability or version gate fails.
DisabledPolicy does not select auto-review.
StartedReviewer starts for the scoped action.
CompletedReviewer returns a bounded outcome.
ApprovedMcode records the approved outcome.
DeniedMcode records denial and stops the action.
Timeout / failedReport the bounded failure state.
Strict detourstrictReviewRequired uses existing manual approval.

The upstream auto-review payload is explicitly unstable. Bound and redact action text and rationale before persistence or UI output.

Verification journeys

Future proof follows the user path across provider, server, persistence, and Review.

Proposed Use the existing verify-mcode runtime workflow for provider evidence and the existing Electron live-testing interface for the right-panel proof. This is a plan for verifier maintenance, not a claim that a verifier ran.

Journey A

Agent-only Codex diff isolation

Trigger
In a verifier-owned repository, one file has agent and user markers. A Codex turn changes the agent marker. After the first live turn-diff update, the verifier changes the other marker in that same file.
Stable result
Review shows only the agent patch, while disk content has both changes. After completion, Last turn keeps only the agent patch.
Evidence
Capture the live update, settled Last turn comparison, and the final file content from the owned fixture.
Cleanup and matrix
Remove only the owned thread and fixture state. Codex is required. Missing provider access is a coverage gap, not a pass.
Journey B

Live-to-settled Review lifecycle

Trigger
Open Review before the turn. Let the live diff appear and update. Complete the turn, then close and reopen the panel and reload or reconnect.
Stable result
Completion changes Live to settled Last turn. The persisted turn diff returns after reopen and reconnect with no duplicate rows or stale spinner.
Evidence
Capture panel state before, during, and after completion, plus the post-reconnect comparison.
Cleanup and matrix
Clean only owned runtime and fixture state. Run for each provider that can supply the selected path.
Journey C

Cross-provider source and fallback

Trigger
Run Codex and Cursor native evidence paths, then the Claude fallback path.
Stable result
The UI contract stays the same. Only the source or fidelity label changes.
Evidence
Capture one normalized ReviewComparison per provider and its selected source label.
Cleanup and matrix
Clean each owned path. Codex, Cursor, and Claude are all required for complete coverage. Missing access remains a coverage gap.
Journey D

Empty, invalidation, and interruption

Trigger
Send a no-change or reverted update, then an empty update after non-empty evidence while file effects remain. Also stop an active turn.
Stable result
Live clears for no-change or reverted evidence. The empty-after-non-empty case selects fallback instead of saving false empty. Stop clears volatile state and leaves the last settled turn intact.
Evidence
Use the live user path where possible. Use focused integration tests for forced invalidation and source precedence.
Cleanup and matrix
Clean the owned stopped turn and fixture. Provider-native invalidation coverage applies where that provider exposes it.
Journey E

Review with warnings and auto-review

Trigger
Exercise a reroute or warning during a diffing turn, then auto-review approved and denied actions, including strictReviewRequired.
Stable result
Warnings do not erase or duplicate diff state. An approved action produces its diff. A denied action produces none. Strict review waits for manual approval before the diff settles.
Evidence
Capture the warning or lifecycle notice beside the Review state and the resulting settled comparison.
Cleanup and matrix
Clean only owned approval and thread state. Record unavailable auto-review capability as a coverage gap.
Later slice 4 journey

An external file change must refresh Files, autocomplete, preview, and Review. Disconnect cleanup must remove owned watches. Add this only when the filesystem invalidation slice is built.
