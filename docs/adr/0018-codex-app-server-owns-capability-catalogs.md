# Codex app-server owns capability catalogs

Mcode will treat Codex app-server as the authoritative source for capabilities it catalogs, starting with Skills from `skills/list` and plugins from `plugin/list` and `plugin/read`. Mcode will expose installed and enabled plugins through the provider catalog while keeping plugin marketplace browsing and management outside this decision. A lazy provider-wide catalog connection will refresh workspace and worktree snapshots in the background, while persisted snapshots remain visible and stale until reconciled by stable entry identity. The connection will stop after 60 seconds without catalog requests because a measured idle process tree used about 95.7 MiB of working memory.

Codex app-server does not expose complete catalogs for custom prompts or selectable provider agents. Mcode will preserve these features through bounded, self-documenting compatibility adapters: custom prompts from the effective `CODEX_HOME` prompt directory, and standalone agents from the effective `CODEX_HOME` and working-directory agent directories. Provider-returned agent registrations may add non-colliding suggestions, but Mcode will not reproduce Codex's internal precedence algorithm or invent built-in agents; Codex remains authoritative when resolving a selected agent name.

Provider catalog entries will distinguish Skills, provider plugins, Codex custom prompts, and future provider commands. Entries of different kinds may share a native name, including a plugin and a Skill contributed by that plugin. Codex CLI built-in commands, plugin marketplace browsing and management, and runtime sub-agent presentation remain outside this decision.
